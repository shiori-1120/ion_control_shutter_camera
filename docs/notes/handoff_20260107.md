## 4. 現状のGUI動作（重要）

### 4.1 397nmの扱い
- 「シーケンスを回していないときは397 ON」を安全側のデフォルトに変更済み。
- 停止時・接続時・ROI check・Snap等で基本的に 397 を維持するようになっています。

### 4.2 Cameraタブ（Snap）
- Snap押下 → TTL送出 → 1枚取得 → `data/output/camera_snap/<timestamp>/snap.npy` に保存 → 表示
- dryのときは `dry_image_dir` が指定されればそこから画像/np を読み、なければ合成フレーム。
- dryの画像は必ず `uint8` の 0..255 に揃う。

### 4.3 Sweep（段階化）

#### Step 1: ROI check
- 397のみ + カメラトリガ1回でフレーム取得し、ROI枠を表示。
- ここでは **光子数分布プロットはしない**（場所として不適切、という要件に合わせて撤去）。

#### Step 2: Threshold（重要）
- **選択中のTTLシーケンス**を `N` 回実行し、その都度 `S_norm` を取得。
- 取得した `S_norm` 配列に対して `quick_threshold_from_samples()` を使い Otsu 由来の `tau` を推定。
- 推定した `tau` を使って **事後分類**:
  - `S_norm > tau` → bright
  - `S_norm <= tau` → dark
- bright/dark それぞれの `S_norm` 分布を、
  - 「画像枚数で割る」＝ **1枚あたりの分布**として同じグラフに重ね描き（`weights=1/N_group`）。
- `tau` を縦線でプロット。
- `threshold.json` に出力:
  - `samples_n`, `bright_samples_n`, `dark_samples_n`, `threshold`（tau/tau_on/tau_off等）, `agreement`

**精度（accuracy）について**
- 実験では外部の正解ラベルが無いので、今は
  - 「単純閾値判定（>tau）とヒステリシス判定の一致率」
  を `agreement` として出しています（自己整合の指標）。

#### Step 3: Start spectrum
- Step 2でしきい値を適用してからのみ開始可能。

## 6. 既知の注意点 / 今後の改善候補
- Step 2（Threshold）の `agreement` は「真の明暗精度」ではなく自己整合。
  - 真の精度を出すには、実験側で ground-truth（例えば準備した明/暗状態）を作る必要あり。
- `quick_threshold_from_samples()` は小サンプル向け保守ロジック（BIMODALでない場合の倒し込み）あり。
  - 分布が片側に寄ってしまう状況（ROI/露光/背景ROIなど）だと `mode=NOT_SURE` になりやすい。
